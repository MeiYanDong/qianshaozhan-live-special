# 2026.6.21 一次带案例的 AI 心法分享…（上）阅读稿

这场分享的核心不是“如何做一个个人网站”，而是借个人网站这个案例，讲一个人在 AI 时代应该怎样把问题想清楚、把 Agent 调度起来，并把一次具体项目变成可复用的能力。

## 一句话主旨

真正值得积累的不是某个模板、某条提示词、某个博主分享的工作流，而是：当你看到一个东西并动心想做时，你能不能从信息获取、流程设计、审美判断、局部打磨、结果验收这一整套链路上，把它稳定做出来。

## 为什么从个人网站讲起

个人网站是最典型的 AI 入门项目。很多人第一次用 AI 做东西，都会让 Agent 帮自己生成一个个人主页。这个项目看起来简单，但一旦目标变成“未来 5 到 10 年真的要用，并且审美、内容、工具、人生记录都要能承载”，它就不再是一个 HTML demo，而是一个长期系统。

讲者想做的也不是一张名片式网页，而是一个能承载文章、工具、人生记录、项目进展、身体数据、财务复盘等内容的个人系统。因此问题从“怎么生成一个网页”变成了：“我不懂前端设计，但我如何确保自己有能力做出符合心意的高质量网站？”

## 普通做法的问题

最直觉的做法是直接让 AI 生成，然后截图、反馈、再改。但这种方式很容易进入抽卡状态：第一次生成靠运气，后面越改越乱，每一步都不可控。

稍微高级一点的做法，是去模板站、作品站、博主分享里找参考，再让 Agent 复刻或改造。但这里有三个问题：

1. 你不一定知道什么东西真的好。
2. 你即使知道自己喜欢什么，也不一定说得清楚。
3. 你说清楚之后，AI 也不一定理解成你脑子里的那个画面。

所以真正的问题不是“有没有参考”，而是如何把参考变成可判断、可选择、可落地的工作系统。

## 第一层思路：先解决“去哪看”

讲者没有先做网页，而是先让 Codex 和 Claude 去调研：中英文社区里有哪些高质量设计参考站、模板库、动效库、组件库、成品案例库。要求不是简单列链接，而是给出社区评价、优势、适配程度、排序和理由。

同时，他又从小红书里快速收集大量相关帖子，让 Agent 把里面的优质来源、设计技巧、复刻方法、截图/录屏传递方式、前端风格拆解方式全部整理出来。

这一层解决的是信息入口问题：不是人自己慢慢刷、慢慢收藏，而是把 AI 当成高强度调研者，让它先把素材池和方法论池建起来。

## 第二层思路：让 AI 先学会“设计师怎么和甲方协作”

光有参考还不够。因为做设计不是简单拼素材，而是要理解需求、避免返工、建立风格共识。

所以讲者让 Agent 继续研究：专业设计师如何和甲方沟通，如何确认需求，如何通过样例理解偏好，如何减少返工。然后把这部分经验和前面的设计调研合并，沉淀成一套“人与 Agent 协作开发高质量个人网站”的流程。

这里的关键是：人的角色不是直接写需求，也不是被 AI 牵着走，而是设计整个协作流程。

## 第三层思路：用样例逼近审美，而不是靠语言描述审美

讲者承认自己说不清楚喜欢什么，但人至少能判断自己看到的东西喜不喜欢。

因此流程变成：

1. 让 Agent 从调研结果里推荐少量高质量参考站。
2. 人快速浏览、收藏真正喜欢的案例。
3. 把这些案例交给 Agent，让它从中总结自己的设计偏好。
4. 让 Agent 基于这些偏好形成初版设计系统。

这一步的意义是，把“我说不清楚的审美”转成“我选出来的样例”，再由 Agent 归纳成可执行的风格语言。

## 第四层思路：好东西不是一次生成出来的，而是改出来的

讲者提出了一个关键判断：复杂页面不能指望一次生成完成。好文章不是写出来的，是改出来的；好网站也一样。

于是他没有让 Agent 一次性生成完整网站，而是让 Agent 拆解：一个个人网站里有哪些可独立打磨的设计维度。经过多轮追问，Agent 从二十多个点扩展到六十多个点，包括导航、Hero、字体排印、文章阅读版式、代码块、表格、状态面板、命令菜单、404 页面、动效曲线、视频嵌入、图片展示、中英混排、分享卡片等。

这一步非常关键：人原本连“有哪些东西可以改”都不知道，但 Agent 可以把专业领域里的可调维度拆出来。

## 第五层思路：每个维度都生成可预览变体

有了维度清单之后，讲者没有让 Agent 写方案，而是要求：每一个维度，结合已经确定的风格、参考网站和设计系统，生成多个真实可预览的版本。

比如导航栏，不是问“导航栏怎么设计”，而是直接给出 5 个不同的导航栏 demo。文章阅读页，不是描述 TOC 悬浮目录，而是直接生成多个可看的阅读版式。代码块、表格、状态面板、开场 loading、404 页面，都按这种方式打样。

这就把不可控的语言沟通变成了可控的视觉选择：人只需要看、比较、选择、备注、要求融合。

## 第六层思路：把选择过的组件变成可落地代码

最妙的地方在于，这些 demo 不是网上截图，而是 Agent 生成出来的代码。因此人一旦选中了某个版本，它本身就是可复用的代码资产。

后续落地时，流程变成：

1. 扫描当前网站对应板块的实现。
2. 回看设计系统和已选样例。
3. 找到所选组件的原始代码和细节。
4. 判断当前网站哪些地方需要改。
5. 对不确定的点向人确认。
6. 一块一块改，一块一块验收。

这样就避免了“改 A 乱 B，改 B 乱 C”的问题，因为每次修改都被限制在明确的局部，并且有对应的参考代码和验收标准。

## 这套流程真正沉淀下来的东西

表面上看，产物是一个个人网站。更重要的产物其实是一个人的设计系统、审美偏好、组件选择记录和 Agent 协作方式。

一旦这些东西沉淀下来，未来再做任何前端页面、封面、可视化、工具界面，都不需要从零开始。Agent 可以直接调用这套风格和决策记录，让后续所有作品至少站在一个稳定的审美底座之上。

这就是讲者说的：做一个网站本身不是重点，真正有价值的是把个人偏好和高质量执行方式沉淀成长期能力。

## 最核心的 AI 心法

这场分享最后落到一个判断：

别人做出了一个东西，不代表他拥有了做出那个东西的能力。他可能只是刚好看到了一个模板、一个提示词、一个教程、一个开源项目，然后复刻出来了。

真正的能力是：当你想做一个东西时，你能不能设计出一套流程，让 AI 帮你完成信息获取、专业拆解、方案生成、局部打样、代码落地和持续迭代。只要你动心起念，你就能稳定做出一个好东西。

在 AI 时代，人的差距不再主要体现在“会不会手工执行”，而体现在：

1. 能不能定义真正的问题。
2. 能不能拆解复杂系统。
3. 能不能设计 Agent 的工作流。
4. 能不能判断 Agent 的输出是否走偏。
5. 能不能把一次项目沉淀成长期可复用的系统。

## 结尾补充

直播后半段还延伸到了知识付费、课程、系统交付和能力复制。讲者的判断是：传统“讲课式知识付费”会越来越弱，因为 AI 可以高速吸收大量资料；未来更有价值的是交付系统、交付结果、交付可复用的 Agent 工作流。

换句话说，不是“我告诉你怎么做”，而是“我把能产生结果的系统交给你”。这和前面个人网站案例是一条线：重要的不是某一节课、某一个提示词、某一个模板，而是能持续产生结果的系统。
