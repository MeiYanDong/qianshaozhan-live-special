### 二、回到主题：个人网站案例的一周进展

[16:55] 今天我们接着上周的分享。上周我讲了一下带案例的 AI 心法分享，用一个个人网站的 demo 来举例，向各位呈现了一套从 0 到 1、从无到有，实现个人网站，并做出高质量、漂亮东西的流程。

[17:24] 各位应该都听过了，也有了一些思考。我们这次开始，就展示一下现在大概可以称之为 80% 完成度的版本。

[17:38] 但是展示之前，我要说一下这一周我认为这个工作流程极有价值的一点。你们应该还记得，上周我调整了里面几个小板块，通过 laboratory 里的演示进行选择、筛选和精确调整，对吧？然后完成了 15% 的基础验证，我发现它是可行的。

[18:05] 上周我就讲，通过这种方式一定可以完成一个完善的网站设计。但是上周我没有讲一个前提：我之所以要设计这个工作流程，或者跟你们分享这个东西，核心原因是我太忙了。

[18:19] 我想搞一个 demo 来演示。这个 demo 我希望明年前哨站都能用上，也就是我的个人网站。但是我没有那么多时间去盯着一个对话框，就为了调这个个人网站。虽然它在多层赋能之后有一定价值，但相对于我当前的核心工作来说，价值依然偏弱。

[18:42] 所以这个工作流本身有价值的地方就在于：我验证了前 15% 的修订之后，意识到一个问题。我需要一周时间，但这不代表这一周我要花很多时间在上面。

[18:54] 我所谓“需要一周时间”的意义是什么？是这个网站按照这个逻辑调整的对话框，完完全全只是我正常核心工作之外，类似 Claude Code 里的一个 by the way 工作支线。

[19:14] 过去这一周真实的工作过程是这样：前面这块屏幕我该干什么干什么，左边挂着个人网站优化的对话。这个过程中，我几乎没正眼看过它一眼。

[19:29] 它一共有五六十项对应的优化细节。整体逻辑就是：推进到下一项，它按照我选择的方式进行调整。打开页面，我看一眼，有问题就用语音输入告诉它“你继续改”，然后我就不管它了，继续完成我该完成的工作。

[19:51] 它那边又完成了修改，让我审判。过了就下一项。下一项的过程当中，每一项它都会把我反馈过的东西、我们调优过的东西、我们固化过的东西，记到设计系统那个文档当中，进行系统沉淀。

[20:08] 过完一项就到下一项，过完一项就到下一项。整个过程让我很感慨的一件事是：里面花时间最长的是什么？是 Claude Code 自己的思考。它可能真的在那里底部转圈，显示 thinking with extra high effort。最多的时间就花在这上面。

[20:34] 一个小板块，如果我有一到两次反馈，可能这个对话框在那里转圈圈、调整二十多分钟。然后我这边完成我的工作，推下一个。

[20:46] 所以你会发现，整个这一周看似过去了一周，但这一周只是我在干我该干的事情，顺带手有一个 by the way 的对话框，一个一个核对细节，一个一个调整参数，让每一个细节都对应到我目前认为“这个初版可接受，有一定审美价值，有一定沉淀价值”的状态。

[21:04] 这个过程当中，我几乎没有花额外的时间精力去打磨它。看一眼，说两句话；看一眼，说两句话。剩下绝大部分时间，它自己在那里跑。

[21:47] 虽然时间过去了几天，但整体上给我的感觉是，它没有影响我主线的任何工作。等于是顺带手就做了这个事。

[21:53] 我希望各位也能意识到：但凡我们用的不是一套高效、严格、每一步明确，并且 AI 和人的分工极度清晰的工作流程，你大致能知道，如果你的个人网站页面设计到了五六十个页面，就是待会我要给你们展示的五六十个页面，按照过往那种屎山代码的逻辑，你去一个细节一个细节抠，几乎无法同时干其他任何事情。

[22:24] 因为在那种积累逻辑和分工不明的状态里，你有大量时间和精力要在解决问题的过程中，解决额外的问题。经历过的人应该知道。

[22:35] 所以这一周我的感受就是：我没有碰到什么问题。没有问题，一点问题都没有。所有流程，五十多轮，全部都是一个状态：那边通过、推下一个；基于我选的，它开始改；改完之后给我一个页面，并且明确告诉我，这五十多页里累积提前了哪些变化。

[22:57] 我去看。看完之后有问题，要么截图，要么直接说。说完它再改。改完第二版基本就差不多了，最多再来一版。还是精准看那几个变化的地方。没问题就过下一个，下一个重复这个流程。重复了五十多个组件和维度，涉及四五十个页面。

[23:17] 体验下来，我感到没有压力，非常流畅，非常丝滑。这就是核心感触。

[23:28] 那我们就来看看，经过一周毫无强度的工作之后，现在大致长什么样子。真的是毫无强度的工作，说出来有点不好意思。

[24:17] 有人说一个月 400 美金。我们目前行业规范不就是 200 美金，你按 API 算就是一万一到一万二美金的 API 价格嘛。我每个月都是 400 美金，所以你别问我烧了多少 token，对我来讲不是问题。不重要。400 不够就开 600。让活儿的人，谁在乎 token 稍微多不多啊？

[24:57] 有人说这是我一顿饭钱。放你妈的屁，我现在一天饭钱就二十多块钱。你说话侮辱我的价值观了兄弟。你可以说这个钱对我总资产来讲不是钱，这没问题；但是你不能说我吃饭要花这么多钱，那我在你眼中不成智障了吗？

[25:31] 等一下，我看这个页面有点什么问题。换到另外一个屏幕吧，这个屏幕比例不太好，显示不出我的水平。我们换一个屏幕。

### 三、网站演示：不是一个页面，而是一套系统

[26:50] 我们先看首页。现在大概是 80% 的完成度，基本属于一个可用网站的状态。但我刻意保持了克制，没有去用特别复杂的动画，因为我觉得意义不太大。

[27:15] 先从启动页面开始。然后这是首页。有一些基础设计，很多排版细节我也没有去调，但大体能看出个一二三。小动画都比较克制。这里有一个进度条，后面放到我自己人生里的时候，我的关键目标也会在这个地方呈现。

[27:56] 这里是工程全貌，会对应到作品和板块。卡片可以滑动，然后是时间表，对应精选文章。下面有一个 CTA、别人的评价之类的，这是网，它不重要。想法关注，这就是我的二维码，我装的。

[28:26] 首页大致就像一个落地页，整体质感我觉得还不错，虽然有些细节还可以再优化。上面有一个 navigation bar，我专门在这个地方用了圆角，其他地方核心走的是零圆角。这里面填充了对应的东西。

[28:50] 比如“事业”这个网站，对应的是马斯克的六家核心公司。未来我希望我的网站里，这里的六家公司对应我当初定下的宏伟目标，也就是一百家公司。所有公司都可以点进去看。我还希望未来能把一人公司逻辑里，公司真实的数据接进来。能对外展示的东西，都能够接进来。

[29:15] 点进去某一家公司，能显示基础介绍。这都比较简单，就是一个文字页面。它还有一个事业反思。当然现在有一个反射动画稍微有点问题，不重要，没空管它，我们先把框架打起来。

[29:30] 然后“思想”这个部分，其实对应的是 article。这个挺有意思，有点小动画，给人的感觉比较克制，还是比较高级。

[29:43] 我让它把马斯克的文章专门找出来，进行排版。点进去真能看到东西，虽然有些是占位符，但有些是真的。比如筛选、卡片视图、标签视图、主题视图，这些都是因为我们之前做 demo lab 的时候说过：不同类型的数据如何排布，对应不同视图的呈现形式。

[30:29] 当前这个是列表，很简单。比如卡片视图，这样看起来挺高级。再比如标签视图，以后每篇文章对应相应标签，这很容易想到。对应标签进行筛选，这个画面挺帅。选定某个标签之后，涉及标签的东西就能出现。没毛病吧？

[30:56] 再比如主题视图，也很好玩。关于文章涉及到的板块，点击一个板块，就能在这个板块里查看对应文章。这里还有会员模块，会员才能看。以后可以是前哨站的人才能看，不是前哨站的人就不能看。我当时就把这个需求写进去了。

[31:20] 除此之外，还有一个年谱板块，也很有意思。这里的背景是侃爷的某个 MV，我把它融进去。像年谱板块，对一个人一年里写了哪些东西，2024 年、2029 年，你注意看，这些设计风格其实非常统一。但你一定要记得，这个风格模板在市面上是没有成型的，它不是套的模板，是 AI 基于对风格的理解自己造的。

[32:04] 这里还有会员解锁，下面也很好玩。除了标签之外，结合 Reader 的经验，上篇、下篇、推荐文章都有。你看上一篇、下一篇、推荐这一篇。还可以啊。包括这些小卡片上面有一些小小的点亮。之前抓到一个小动画，但我觉得有点浮夸，就让它稍微克制一点。

[32:48] 文章页除了内容排版，中英文混排也比较悦目、比较克制。引用也符合这个风格。旁边有目录，小圆形的目录是我挑的，点击目录可以跳转。这些功能都不是什么问题，但整体这种审美的感觉，这种克制、主题化的风格，给人一种浑然一体的感受。至少这是我个人的感觉。

[33:23] 你仔细看，会发现右下角，当页面往下滑超过三分之二的时候，会出现一个回到页面顶部的按钮。它是渐进出来的。三分之二以上才需要回到上面，点它真能回去。以后文章长了也可以用。看起来比较高级，实话说，不涉及动画的时候，这种黑白高级质感其实也不太需要太多动画，太多反而没有高级感。

[34:07] 左下角也是一个组件，叫设计组件。之前你们应该还有印象，我们说它会有对应的命令行。如果点命令行，真的会出现一个命令面板。包括在里面按 command + K，也真有命令面板。功能还没细设，但它可以直接进到里面的板块，比如刚刚说的“思想”，点进去就回到思想主页；点“生平”，就进到生平主页；点“当下”，就进到当下主页。

[34:44] 还有设置面板，比较简单。后面我希望我的个人网站可以主动向各位开放 RSS 订阅。这样大家不用再去找 RSS，直接订阅，有更新就能看到，挺好的。对一些简单设置，我们先打个样子，大致就是这个意思。

[35:10] 除了思想，还有一个部分叫“系列”。这个也很好玩，我觉得设计很精致。什么意思呢？就是专题文字。比如当年我写过一篇《我为什么一定会财富自由》，那可能就有一个定文叫“财富自由三部曲第一曲”。类似马斯克当年发的特斯拉 Master Plan，Part 1、Part 2、Part 3 这种感觉。它是专题类的东西。

[35:44] 我们可以把它整理到一起，方便专题化阅读。你看右边更新进度百分比，一共有多少，当前更新了多少，完结没完结，我感觉细节还是挺好的。进来之后以专题为导向，引导到具体文章排布，挺爽。你有了前面文章里的元素，比如标签、导航、主题，想分专题就很简单。

[36:26] 然后“生平”这个部分，人生时间轴，历史沿革，做得也比较简洁。马斯克传里不是有马斯克从小时候一路梳理下来的生平吗？按年份排。万一以后有人好奇我的年度进展，或者人生历史曲线，对应什么呢？就是这个。

[36:57] 这个页面也可以再加一个右侧类似目录滚动条的东西，帅帅的。人生的大阶段，每个大阶段里的年份，年份里的关键节点，完成了什么样的事情。这个值得看一看，真挺有意思。

[37:16] 然后“当下”是干嘛呢？当下就是我在校长老师个人网站里看到的启发，好像是 recently 或 now page，就是这个人当下正在干什么。

[37:27] 举个例子，我之前跟你们讲过，我每天健身的信息是用飞书让 AI 帮我管理的。我现在已经跑了二十多次步，健身也二十多次，瘦了八到十斤左右。每次跑完步，我都会记录步数、配速、心率之类的数据。iPhone 健身 App 会生成一堆数据，我直接发给 Claude，让它帮我整理，包括步频、速度、心率、热量、体重这些。

[38:14] 所谓 recently 就可以看到：跑步、健身、健康管理这个板块，是我最近正在更新的。如果我的 Claude Code 能获得这个数据，网站就应该实时更新掉。今天确实又跑了，任何人都能看到王正宇跑步的最新进展，类似这种感觉。

[38:35] 包括原著阅读最近读到哪了，也是一样。因为这些东西都是数据化的，我只需要把数据接口接通。它每天定时一个 loop 或 schedule，把所有信息源入口扫一遍，扫完之后直接推到网站里。理论上，如果有人在乎的话，它可以实时跟踪我当前在做的所有事情。

[39:00] 包括真实生活、工作和生产，做这个项目、那个文稿、那个内容。因为都是用这些工具生产的，只要你有衡量标准，比如能不能接到飞书里的任务管理、项目管理，能不能接到自己的工作管理。如果都可以，哪个项目什么进度、做到什么份上、还剩多久，理论上全部可以通过 recently 进行直观展示。

[39:32] 我当时就做了一个设计：当前最重要、此刻聚焦的东西，下面是 launching、shaping、scaling、building 等。我举个例子，当前只是比较粗略的版本，大致打这么一个样。下面是当前脉搏，一些关键数据做到什么、走势怎么样、关键指标怎么样。你们看这个组件会觉得眼熟，对不对？就是我们 lab 里面分了好几个维度，各个维度里出现的东西，它一个一个跟我过。

[40:18] 甚至还有倒计时，距离目标还有多久。你们觉得这里我会放什么？很显然，我会放我的七十年人生倒计时。距离我七十岁还有多久，我的关键目标目前完成进度怎么样，逻辑上很合理吧？

[40:37] 再比如“关于”这个部分，就是介绍人。下面是一些关键指标，再下面是 Bento box 板块，就是苹果开发布会用的那种核心设计。对应一些跟这个人有关的核心入口，下面也用了一个类似菜单栏的组件，关于这个人的核心介绍，以动态方式进行点选和呈现。

[41:27] 前面已经有了 navigation，我又做了一个 menu bar。这个 menu bar 点开很帅，当然跟分辨率也有关系，适配还没做好。你看，是不是很像 Windows Phone？我不知道里面有没有人用过 Windows Phone，Windows Phone 就有这种风格。PlayStation 也有点这种感觉，算是微软延续下来的一种设计语感。给我的感觉很高级。

[42:10] 刚刚上面这些交互，我还做了一个类似锤子科技麦克风、听筒和扬声器网孔那种小小的设计。点它，它会滑到右边，弹出一张扫码卡。点击关注。然后点这个，会有右侧滑动的效果，弹出分享页面。这也是它给我的建议，说可以有这么一个元素。

[42:55] 除此之外，还有一些关键组件没有在导航里显示，这也是后面交互入口逻辑要思考的问题。比如内容层面的“马总语录”。但我觉得这个动画有点傻，我不太喜欢这种渐进出现的效果，希望它更精简一点。

[43:19] 语录库可以进行标签、分类、按年份索引。其实这个部分更像我前面说过的个人原则系统。我觉得这里可以把它变成一个原则交互区，呈现我目前沉淀下来的原则。因为我不会觉得自己有什么“语录”值得参考，但对我个人而言，这个网站除了大家能看，我自己也要能用。所以我希望它能够呈现前面讲过的个人原则体系。

[43:56] 再比如演讲部分，把马斯克的演讲放下来，连在一起，形成展示区，点进去之后真能播放。以我这种标准来讲，以后放直播回放、发出视频、生活记录，把它变成对外交互窗口，汇集所有东西，我感觉还是挺有意义的。

[44:51] 影像部分是关键照片。这个地方还挺帅，像一个摄影集一样。以后放我的照片，应该也会挺帅。联系入口、订阅入口也有。不要花里胡哨，人家都戴着耳机工作，耳朵里有自己的音乐，你不要给他整这些东西，没有用。

[45:42] 有很多花里胡哨的东西，我都删了。我不要。我觉得它不够克制。高级就要体现在克制当中。花里胡哨什么都往里夹，就会似像非像，没有水准，没有档次。

[45:55] 这些地方有些小组件动作，有一个小小的动作方，相对克制，还能保持高级感。订阅、推送、RSS 之类的，大体就是这样。基本上属于 80% 程度、可用状态。

### 四、这次项目真正沉淀下来的东西

[46:22] 后面要做的事情就很简单。框架已经有了，每个板块对应我心中的什么，再把相应内容填好。

[46:30] AI 需要了解我什么？我肯定不会挨个回答问题，那太傻了。因为我跟 AI 已经协作这么久了，而且我说过，每一次工作的沉淀，AI 都会去沉淀我的个人特质、工作流程、目前拥有的资源和一些特性。

[46:51] 所以要填这个网站，绝大部分文案我都不需要给它，因为它了解我。它直接帮我填就行了。实在不知道的，把剩下有疑问、拿不清楚的部分，再跟我搞一个访谈就行。问一个问题，我答一个。答完之后，把马斯克版本改成我的版本，后续过程理论上非常轻松，非常简单。

[47:19] 所以这个几乎已经成了。上周其实就已经成了。但到这时候，把 85% 的东西放进去，优化进去，让它做板块之间的组件联动，完善之后，才能看出大体全貌。

[47:35] 整体上，我个人觉得它是一种高级又克制的风格，而且不是那种按照黑白极简风套模板套出来的场面。更重要的是，这一周我其实没有花什么额外时间和精力。唯一做的事情就是：它在左侧副屏上跑，有问题问我，我打两句话，跳下一个板块。

[48:06] 同时，它给我沉淀了一套依托于我审美标准、可复用、可通用的设计系统文档。通用设计系统文档有什么好处？上周我跟你们讲过，一个亲自走完这个过程很有意义的事情，就是一旦在我的审核、它的提醒、我们俩协作的情况下走完设计系统沉淀，再加上 lab 里面本来就对应各大组件有一些板块，我们几乎就可以确认：未来在自己的设备上做的所有前端设计，至少有一个可以参考的稳定风格了。

[48:59] 从此之后，未来所有从我的设备里产出的东西，都有一个基础质量根基作为保障。

[49:08] 做完这件事之后，我又做了一个测试。你们应该还记得，一个多月前我讲系统思维的时候，提过我每日 GitHub 开源项目的学习库。当时我用 UI/UX Pro Max 的前端设计思路，简单搞了一个页面，也没怎么优化，因为无所谓，功能优先嘛。

[49:58] 有了个人网站沉淀的设计系统之后，我就让 AI 参考这个设计系统，直接把那个东西改版。它就把它改成了现在这个页面。风格是极其统一的。

[50:15] 这就是我想说的。虽然这只是一个页面 demo，包括里面可能还有其他想法可以调整，但不重要。重要的是，如果它能一次性改成这样，就意味着你做任何东西，从第一次出图开始，就能够保持那个基准标准和风格，出一系列稳定的、一看就是王正宇做出来的东西。

[50:41] 于是它就从一个 demo、玩具级测试，变成了一个借此机会给系统沉淀全局级风格锁定的复利资产。

[50:58] 这就跟之前开源项目里 Google 那个 design.md 是同样逻辑：沉淀你的 design.md 文档，去指引全局相关设计，让你的出图、出活能够统一对应风格。这个测试让我清楚感受到，这是非常愉快的一件事。

[51:22] 以后我就不用再用一个前端设计的 skill，告诉它这个风格、那个风格。如果我说太多，又浪费时间；如果我说得不够细，它又瞎做，改的时间很多。这一次满足我要求的东西，我只要搞出这一版，多的就不用说了。我甚至都没有 skill，直接跟它讲：现在我要把这个页面改成某种风格，用个人网站页面的设计系统去打造这个前端页面，你按那个来就好了。

[51:55] 这个页面你不能说它多么惊艳，但统一审美逻辑之下，80 分是有的。给人感觉是高级的、克制的，满足之前那个风格标准。这就是完全不一样的概念。没有那么多不确定性需要我思考，而是按照我的要求给到一个标准。这个标准一旦定下来，以后可能用十次、二十次、一百次、一千次。

[52:23] 如果是这样的话，我在这个项目上花的时间突然就显得很值得了，而不再局限于每个项目本身。

[52:33] 所以从这一周成果来讲，刚刚的演示就说明，上周讲的整个工作流程是清晰、明确且适用的，是可以简单拿到结果的。

[52:54] 除此之外，甚至还不必说另一件事。假设这个设计风格依托一次定在这里，下一步能干什么？如果 token 够的话，将来我会把 laboratory 从个人网站设计拓展到全域网站设计。什么意思？不是做个人网站，而是各种前端交互类网站所需要的板块，全部给我拓展开。

[53:18] 拓展还是一样的逻辑：你别跟我扯，我也不懂。网站参考权给你了，你去调研。调研之后，如果给我 120 个维度，每个维度还是一样，基于同一风格，五个可选项。五个可选项里有一个对了，基于这个再来五个。

[53:51] 那我就有了 120 个组件板块维度，可用于全网站交互设计的同风格组件。这些组件的特点是：它本来就是依托这个设计系统来的，所以没有改动问题。你只要知道这东西想用在哪儿，它就能直接用进去。代码不会出错，你说放哪儿就放哪儿，说干嘛就干嘛，非常精准。

[54:35] 如果是这样，这 120 个组件以后要做的可就不再是所谓个人网站了，而是所有东西。甚至，如果这个过程中能找到更多行业设计规范或网页设计规范，我们能不能给设计 skill 里做一个以这个风格为基础的流程？当你做网站设计时，梳理完需求，在 UI/UX 行业规范里，这个东西应该由 120 个维度里的哪几个维度解决，你要能明确。

[55:21] 如果到这一步，我们还愿意再多做一步，不仅沉淀你认为好的设计系统，还沉淀你在做这五十多个组件判断时的选择标准。它把你的选择逻辑、判断标准也记下来，那就意味着它不仅能给你一堆同风格选项，还能知道你当初为什么这样选。

[55:53] 这是不是在代替你了？一个子 Agent 就出来了。这个子 Agent 专门沉淀了王正宇对风格的理解和选择逻辑。它专门在 120 个维度和每个维度的五个选项里，代替我去做选择。

[56:13] 那我就完全不用插手了。我只需要说：我要干这么个事，有这么几个功能，每个功能大致是什么逻辑。讲清楚了以后，它先按照 UI/UX 设计规范给我规划：每个部分分别需要哪些组件，每个组件在那 120 个里怎么选。然后不是盲选，而是让沉淀了我选择逻辑的那个子 Agent 做审核。你选，它审；不过就再选。

[56:41] 里面所有东西敲定之后，它就走完了这一周我跟它五十多个挨个过的过程。只不过它走得比我快，因为我是人，肯定慢。它 120 个维度，刚刚做完之后，所有东西全出来了。虽然多了 70 个组件，多了 70 个维度，但风格统一，审美再现。不知道的人以为我参与了很多，其实我完全没参与。

[57:09] 这个逻辑就是：在上周的逻辑里，我们又加入了审美标准的沉淀，又加入了审美人工卡点的替代。如果这一点也被替代，整个过程我就不需要参与了。第一遍我需要参与，因为没有第一遍，它不知道我要的到底是什么。有了这一遍，它大致就知道我要什么，以后就能给出满足同一风格、我大致要的东西。

[57:40] 再举个例子，有了这个风格，市面上一些所谓 PPT skill 跟我还有关系吗？当然可以拿来用，但我不必要了。我都有这么一套很帅的风格了，我演示不就用它做吗？有了这个设计系统，我要拓展个人 PPT 制作包，跟玩一样。开源 PPT 设计拿过来，选版式，不选风格，因为风格我有。至少让这个风格层面里的 80 分基准定住，然后用这个风格选择版式流程，稍微优化一下，同样风格的 PPT 就来了。

[58:37] 你说如果不这么思考问题，这种积累不重要吗？看似我做了一个 demo 在玩，但你想想，这里面的复利难道不大吗？

[58:44] 再比如，有了这个设计系统，以后前哨站的封面能不能按这个系统来？你们一看黑白灰，某些说不清道不明的元素，就会定义老王至少有一个风格是这样。那封面不就有了吗？小红书、抖音封面，改改透明度，改改反射逻辑，是不是也有了？

[59:11] 如果能上升到这个维度，就几乎意味着你的 Claude.md 里可以直接写：所有视觉呈现的东西，优先参考这个设计系统。后面很多就不用管了。当然 Claude.md 权重太高，我还是建议不要乱放，没必要。但逻辑上是这个逻辑。

[59:42] 你会发现，我做了这么一个小 demo，或者所谓个人网站，留下的是什么？留下的是一个可复用的资产包，赋能未来各个板块里涉及同类需求的东西。如果按这种方式做事，这个活的价值就比单纯做个网站、单纯研究个 skill 高级太多了。

[01:00:11] 这个过程是一边做一边沉淀下来的。它还沉淀了什么？还沉淀了 AI 梳理 design.md 的流程。因为我发现，按这个方式，你参考了东西，要的是维度。我当时给了十个参考网站，还有它的来源。那它启发了一个问题：你的工作空间里何必只有一套设计系统？

[01:00:52] 梳理整个过程，我从头到尾只给了十个网站。我觉得风格还可以，就挑了这十个，偏黑白、科技、极简。反正我描述不清，但我有点感觉，就这十个。然后呢？它自己梳理的。过程中我还做了什么吗？我什么都没做。

[01:01:16] 组件是它生成的，风格是它理解的，系统是它沉淀的。我就把握它说的跟我要的是不是一样的，通过落地效果判断它理解对不对。每个细节，我都能把握它说得对不对，做出来好不好，靠不靠谱。

[01:01:46] 既然我只给了十个我认为好的网站，又在过程中当了一个判官，那你的设计系统里何苦只有一套风格？按这种落地逻辑，120 个维度都可拓展，每个维度之下 5 到 10 个 sample 可以直接拿来用。

[01:02:02] 这比平时你在网站里复制一个模板，或者用语言描述某种代表性风格，要精准得多。你平时说“我要一个那种风格”，说完剩下就说不清了。它落地一半，其他东西不符合。为什么？因为你没有组件可挑，没有组件可选，无法精准制导它完成后续推进。

[01:02:29] 我们解决了这个问题，而且解决这个问题的过程没有多花任何时间精力，就给它十个网站。那如果我除了科技风，还有另外喜欢的风格，再找十个网站，把整个过程当成工作经验、设计组件、组件审核、MD 沉淀，再走一遍，能不能等一套新风格和组件库成型？肯定可以。

[01:03:30] 完成之后，纯沉淀，来八套吧。但我这八套可不是别人说的“网站参考链接”那么简单。我每一套都是这个维度下我挑的十个最喜欢的东西，深度理解和拓展出来，并且每一个背后都有 120 个维度可选、可替换、可直接上手用。那不是想做什么做什么？这就太有意思了。

[01:04:07] 这只是用个人网站前端设计举例。但我不知道你们有没有体会到：你要怎么在 AI 协作过程中理解自己的可复利资产？不是有问题现场解决，而是要把自己的人生、大家工作的工作区、每一个板块、每一个环节，当成一个有机整体去通盘考虑，看成一个共同进化的整体。

[01:04:37] 彼此之间的赋能、协作、复利效应都考虑进去，这个问题越琢磨越有意思，越琢磨越有味道。

[01:04:55] 好，我们先休息三五分钟，回来继续。

### 五、复盘一：先把工作流想透，后面才不会乱

[01:10:06] 好，我们继续。我刚刚琢磨了一下，感觉今天可能把今天的心法讲完就差不多了，剩下那个细节下周再说。

[01:10:20] 我来带各位复盘一下，整个过程当中我体会到的一些比较有意思的点，可以作为你们未来探索 AI 过程中的一些心法和提醒。

[01:10:35] 我们想到哪儿说到哪儿，就当吹牛了。先复盘整个过程。第一件非常值得思考和总结的事是：如果你对 AI 的理解还算比较深，你会发现，人们普遍讲的“对话太长、上下文太复杂、活干到一半就开始瞎搞”这个问题，其实有几个理解维度。

[01:11:16] 举个例子，我们整个网站开发的心路历程分成了几个板块：从一开始什么都不知道，到调研设计规范，到询问设计规范，到明确工作流程，到每个步骤人机如何协作和分工。

[01:11:31] 你看，我们在上一次还没有落地完成的时候，我就已经给了这个结论。我说下一周会怎么样，会是什么结果。我想跟大家讲的是，如果你对 AI 理解比较深，大部分时间、精力和思考，在一开始就应该落在整个工作流的梳理和打磨上。

[01:11:51] 如果这个地方思考得足够深入，这个活怎么干、干成什么样、在什么地方能出错、能不能出错，你从一开始就是知道的，就没有任何所谓的不确定性。

[01:12:05] 很多人的理解不一样。于是人就分成两波：一波人在不确定性里面找确定性；另一波人在确定性里面找不确定性，或者找提拔亮点。两者的核心区别，就是你作为一个人，对这个活的核心流程边界掌握得细不细，理解得深不深。

[01:12:33] 这个部分又涉及你对 AI 能力边界的理解。比如你一开始让 AI 调研，它当然适合干这个。但我知道它调研出来的东西，两个外国和尚，可能有时偏颇，不太符合咱们国情。这就是我在这个环节里对它能力的判断。

[01:12:58] 为了解决这个问题，我才亲自下场，说小红书的东西我给你一点，咱们两个综合一下不就齐了吗？至少入口端就齐活了。

[01:13:08] 有了入口端，下一步要有行业规范才能做好对接。为什么？因为它的调研能力，完全可以从开源项目、公开资料和通用知识里沉淀出一个设计师和产品经理之间对齐的核心流程。总比完全不懂好。

[01:13:29] 有这个框架，后面活干起来就会轻松很多。所以第二步要让它去干这个活，才能让后面的工作流，在专业行业知识帮助下，形成一个相对清晰明确的标准流程。

[01:13:45] 这个第二步，就决定了整个过程不会是普通人一上来就干到哪儿算哪儿，打一枪换一炮那种割裂状态，而是有一个核心框架在束缚。每一步做完之后，下一步干什么，需要什么，都给了你把握全流程的可能性。对整体可控性的感觉，就会明显好很多。

[01:14:14] 然后落到风格参考这件事上。上次我们说过，你必须知道：当你的语言表达很贫瘠，或者没有足够多参考的时候，你无法期待任何能力的 AI 一次性给你理想中能够触动你的好版本。

[01:14:37] 因此，在风格层面上先确定大方向，才有后续进行精细调整的可能。想到这一点，你才知道第三步给大方向就行，不需要精益求精，更不需要在大方向上跟它琢磨非得一二三。你给我五个，我挑一个不错的、能让我满意的就行，因为后面还有大量空间做细节调整。

[01:15:11] 如果你本来就有一套设计系统可以替你描述，或者你的 prompt 写得极其规范、极其细，甚至每个部分都给到了对应参考，那唯一要落地的问题可能就是它的注意力问题。这种情况下分段就解决了，不是问题。

[01:15:33] 可问题是，我们作为外行，压根写不出那样的东西，也没有那样的东西。没有怎么办？只能退而求其次，先从大方向来定义，让大方向不变，再去扣细节。

[01:15:49] 到了扣细节这个部分，又涉及一个问题：细节怎么改？截图复刻不完美怎么办？不同风格要融合组织，瞎搞怎么办？这些都是你对当前 AI 能力的判断，一开始就能想到的问题。

[01:16:10] 因为能想到这个问题，所以一开始就从工作流和架构上解决。我们的思路是什么？只参考它的组件怎么做、是什么效果，但所有组件不要抄代码，不要把别人代码拿过来硬融进去。因为改别人的东西、融进来，容易出问题。

[01:16:29] 你的目的在于：让 AI 理解大方向之后，按照同风格生产组件。这个能力它几乎是完美的。大方向对了，它自己写出来的东西，我可能看不出专业的一二三，但我能选出优劣好坏。

[01:16:48] 这样对应的问题远比把别人东西硬拿过来、非要融到你的风格里少得多。因为它不存在去伪存真、取其精华、去其糟粕、对比权衡，然后耗费很多上下文注意力的问题。它就是风格大方向在这，你按这个理解自己来。这个过程不容易犯错。

[01:17:17] 风格一旦统一，又解决了下一个问题：如果组件要融入页面，它因为底层东西是自己写的，风格又统一，无非是放在哪儿的问题。它干这个活，思维负担很低，注意力不怎么被稀释。它盯在哪儿做哪儿，做哪儿就是哪儿，几乎没有额外改动。

[01:18:08] 所以你从一开始思考，就能知道这个过程每一环肯定通畅。更重要的是，这里面几乎没有给你留下基础债的可能性。不存在做到一半要拐弯，不存在一半发现思路错了。因为一开始就想得很清楚。

[01:18:38] 最后一个问题是：如果有一个组件你很喜欢，要落地这个组件，那就让它单独为这个组件去建相应页面。所有维度挨个过，过完每个里面都确定之后，对应页面自然也就出现了。那些页面也有前面的大风格和落地组件作为参考，整个过程是很稳健的。

[01:19:01] 到最后就是：这个活不能白干。不白干的意思是，每一步都要留下未来可复用的知识资产。这个知识资产，就是每过一个组件，我都让它沉淀设计系统。

[01:19:14] 设计系统除了最基础的风格描述之外，还要知道：有了组件，组件是有代码的。你就有了所谓风格描述词对应具体什么代码。甚至如果有必要，组件呈现或整体风格的截图，也可以作为附件放在设计系统里。以后任何时候调用，都能清楚理解回到第一现场，理解我们说的到底是什么。

[01:19:48] 于是这个设计系统就变成：整体风格是什么，如何描述，涉及哪些具体板块，每个板块有什么要求，有哪些参数，每个参数有什么风格设定。每一个细节都对应具体代码说明，它要看可以直接看代码，也可以看到当初实现的具体截图。

[01:20:18] 这个设计系统在未来就有了长期复用的可能性。AI 可以充分相信它。只要它在，每次复合它都会有稳定质量。因为它有代码可以参考，有软的描述，也有硬的东西。两者一结合，标准就很稳定。

[01:20:42] 抽象出来看，我觉得重要的提醒是：很多所谓问题和困境，不是某个单独局部点碰到的，而是一开始没想清楚，没想明白，没把思路理清楚。你一开始瞎干，越干越乱。而我们的大脑带宽和思考能力早就证明了：一旦局面乱了，你在乱局里还想梳理出一条清晰的路，大概率就推翻重来。

[01:21:13] 刚刚我拓展说，组件库本身还能拓展，风格本身还能拓展，应用场景本身还能拓展，不仅是个人网站，各种设计都可以参考。整个项目的价值，就提前出来了。

[01:21:30] 但核心还是这个：从头到尾我都没觉得这会是个问题。我从一开始琢磨这个事，就觉得大体思路几乎是铁定正确的。无非过程中稍微动动脑子，在什么地方补一点判断、补一点思路。

[01:21:50] 唯独各位要了解，这个方案是我推翻了它给的两版工作协作流程之后得出来的。它前面给的两版非常流水、非常刻板：我怎么问你、你怎么确定、挑几个帮你落地。甚至流程错到“选一个风格，然后一次性全落地”。这明显是错的。

[01:22:22] 你有没有挑 AI 方案错误的底气？这一次我明显感觉到：唯一值得挑错的地方，就是定方案和流程的时候。这个时候你都不动脑子，觉得这都能交出去，那这个事基本就黄了一半。

### 六、复盘二：流程和智能是一对需要匹配的东西

[01:22:42] 第二个，我整个过程中体会到的一些心法层面的东西，是希望各位形成一种感知：你具体每一步到底在调用 AI 的什么能力，它能力当前的边界在哪里，长处在哪里，你心里要有数。

[01:23:11] 我经常举一个例子：你在用 AI 的时候，一个明显感觉是，流程和智能是相配的。所谓稳定执行和智能释放，这两者是相配的。

[01:23:22] 我一直把 AI 理解成一种非常聪明、但你给它自由空间它就会瞎发挥，甚至带着你都跟不上节奏的生命形式。有点像我高中的时候那种数学每次考 148、从来不听课的学霸。你问他题，他讲题思路是跳的，你听不懂。

[01:23:51] 但我们在工作过程中有两个需求：一个叫稳定的工程实现，另一个叫灵感性的智能释放。几乎所有工作都是在这两个极端里找一个平衡点。

[01:24:11] 如果你在某个环节里希望 AI 释放很多智能，给你很多灵感、启发、经验，那么你就要想到，这个时候 AI 大概率无法稳定执行。当你需要 AI 稳定执行的时候，你也要知道，它大概率就是一板一眼听你的话，做你告诉它该做的事，甚至不一定能够稳定完成你的目标。

[01:24:37] 所以我前面分析过：当前 AI 应用赛道，就是从纯粹的脚本代码，到完全的 chatbot 聊天，这么一个光谱过渡轴。最稳定的方式是什么？写成死的代码，代码执行相应功能。它最稳定，几乎不会有变量，因为写死就是写死，不涉及智能释放。AI 的智能被用来写代码，代码解决问题。

[01:25:14] 而 chatbot 呢？它不用干任何落地，就是聊天、启发。我们前面做的所有工作，workflow、MCP、context engineering、prompt engineering、skill，这一堆东西，都是从稳定到智能释放的光谱过渡。

[01:25:50] 你应该理解每一个功能、特性、command、技能，位于这个轴里的哪个位置。在那个位置上，它更多涉及智能释放，还是更多涉及稳定执行。

[01:26:08] 比如调研这件事，更多用工程能力还是智能？我觉得顶多用了 web research 和基础大语言模型整合功能。稳不稳定不重要，最后核心是把结果放到文档里。这个环节，我理解它更多偏向稳定工程能力：你给我这个结果就好。

[01:26:39] 什么时候明显用到智能释放？就是小组件设计的时候。我知道这个时候我的核心，是基于这个风格，让它释放自己的灵感，给我更多可参考的、甚至让我觉得惊艳的东西。你就撒开了来，不要有任何限制。

[01:26:55] 我看好了哪个，就点它。点完它就从撒开的状态收一点，带着约束条件再释放一下。每一个工作过程里都存在这样的判断：在这个步骤用什么方式设计流程，实际上设计的是你对这个工作流细节里“稳定工程”和“发散释放”比例的理解和把控。

[01:27:24] 有了这个理解，你就能更好思考这个步骤应该怎么设计，或者更具体地说：你需要用什么工具实现相应功能。很多人的大脑里没有这个认知框架，整个人都是稀里糊涂的。

[01:27:50] 再比如定方案。定方案很明显是智能释放。所以但凡意识到这个步骤核心是智能释放，我就从来不相信它。再强的模型也一样。但凡涉及猛烈的智能释放，我默认不相信它。

[01:28:19] 到这个时候，我就知道我要停下手里的活，认真读、认真思考。如果我给到一定限制条件，让它的思考收束回来，它整理方案的能力没问题。但是它设计方案本身的能力，我一直存疑。

[01:28:38] 什么时候会稍微好一点？就是这个方案本身你已经给了足够参考，给了相应限制。在这种情况下，方案相对可控。但如果你只说个虚的，让它瞎来，我几乎从来不信。

[01:28:53] 这个时候你的输出可以停。停下来，读这个东西。读完之后，看能不能给它更多限制条件，更多切入视角，更多明确要求。给完之后再调，调完才会倾向于可用。

[01:29:10] 所以现在我很谨慎：给个方案直接做，很恐怖，一般干不了。但我不是只说“方案要谨慎”，我更希望你们在每个环节都从这个维度去理解：稳定和灵感，在那个步骤你到底要的是什么。如果要的是稳定，你就要知道灵感一定欠缺；如果要的是灵感，你就要知道稳定一定欠缺。这个时候你怎么协助，就涉及人机协作边界。

[01:29:49] 第三点也很明确。所谓人机分工，在这个过程里很明确的一件事是：到现在为止，人到底还适合干什么？

[01:29:57] 整个过程当中，我很明确一点：现在人的视觉能力还是比 AI 强。基于视觉，对整体风格的感知、喜好、嫌恶，人比 AI 强。或者说，整个过程中我也就只有这一点更强。所以我重点就干这个。

[01:30:18] 我说，用文字给我叙述设计的时候，我看不懂，也听不懂。我唯一能懂的是：你用这个系统生成对应东西，我看它爽不爽。爽，那你的设计就没毛病；不爽，就有毛病，你改。怎么改我也不知道，我不懂嘛，你改呗。改到我爽了，那就行。

[01:30:32] 于是我用我所长，把这个长处用到尽可能丰富和充分。整个过程中，我做大的方向和风格判断。所以我不可能让它给我写死一个方案，然后一句一句告诉它怎么改。一是我语言能力贫瘠，二是语言说不清楚我到底要什么，三是我都没见过那么多我要的，我不知道我要什么。

[01:31:01] 一开始就要定下这个基调：你能力强，吞吐快，有一点理解之后，噼里啪啦给我一堆。我看就行。你给五个也行，十个也行，对我来说就是三分钟和十分钟的区别。我挑一个，说按这个来。相对稳定就有了。

[01:31:22] 组件部分也是。你给一个我肯定不满意，但我又不知道有哪些满意的。那行吧，你不是发散能力强吗？来吧。你发散之后，我适合看的就看，看完认为这个好，那就给它一点约束，再稳定一点。就这么一个博弈过程，两者成分不停切换。

[01:31:53] 这就是很明显的人机协作边界。首先，工作流你要心中有数；其次，每个步骤要干什么，你想得比较明白；需要什么，它做什么，你做什么，你俩优劣势分别是什么。站在更高视角思考整个过程，你会发现，从一开始就知道最后结果一定不会差，至少是 90 分以上。

[01:32:29] 这只是设计过程。你们做很多其他活也是一样的。但很多人没有这些细节思考，理解没有扎根在这里，所以每个过程可能都是迷茫的，甚至是顺从的。别人端上来什么，你都照单全收，都推进。

[01:32:59] 一开始肯定是这样干的。但后面你会发现，我们不一定懂一个事情里所有细节，但关键刻度、关键维度上，你必须是一个思考足够深入、相当懂行的人。只有这样，你才能抓住里面的要害。

[01:33:13] 现在我觉得，一个三千字方案，如果有七个步骤，七个里面我能挑两个，指出里面关键误区或者工作思路漏洞，整个项目推进质量就会因此大大提高。因为你要抓的是最关键的东西。

[01:33:26] 抓大放小的逻辑，在这个时代更加明显。80% 那些字、提供 20% 价值的东西，AI 直接给了，你也不需要改。为什么？你就当花絮，直接改了影响也不大。但里面提供 80% 价值的那 20% 的东西，才是你要认真识别、找到，并且彻底理解的关键。

[01:33:52] 理解不清楚，就要反复追问。问明白、问清楚，确认你认为干这个事最好的思路真的就是这样，这个活才能成。如果你细部里细部全都通过了，那就等着平庸吧。

[01:34:08] 我昨天听项目介绍的时候分析了一个事：AI 这种大语言模型，基于统计规律训练，还有一个特点。你不要看它智能释放好像很猛，但落到任何一个具体落地板块，它只能给出平庸的东西。

[01:34:33] 这跟它的训练方式有关。它综合汇集了大量东西之后，最后凝练出来的那个东西，就是在那个板块上最正中、最平庸、最不犯错、最能满足人们对某个抽象概念理解的版本。偏一点点，可能就有人觉得偏激。所以它给的一定是符合刻板印象、最平庸的中间量。

[01:35:13] 正因为如此，你让它找解决方案也好，设计思路也好，往往会觉得：以它这个智力，不应该只提出这种水准的东西啊。你会觉得不配它的智商。但这确实和它的架构、训练逻辑有关。

[01:35:52] 它提到一个概念，理解这个概念就是正宗、没新意的版本。它所有概念基石都是这种状态。于是，一堆平庸概念在正常情况之下，不逼它、不提醒它、不给限制，它给的就是中庸版。你再通过中庸版做一个中庸的东西。

[01:36:16] 所以你的任务就是：在中庸里面挑出不该中庸的地方，给对应板块不中庸的可能性、限制条件、提醒和启发。不管你用文档、沉淀、提示词，还是语言给它，都无所谓。总之，挑出那些东西之后，就是二八法则里发挥 80% 价值的、需要你专门调整的 20% 关键。

[01:36:51] 每到这个时候就要打起十二分精神。项目卡在那个地方一天两天都无所谓。多抽烟，多去跑步，多去冲凉、洗澡，让脑袋里挂着这个事。你要知道，你几百的智商如果 90% 精力放在一个点上，要比 150 的智商注意力分散到各个板块、全部求平庸时，更容易带来刺激和启发。

[01:37:15] 人在这，就要干这个活。如果你的核心重心不在这，那活就白干了。设计就是非常典型的案例。

### 七、复盘三：越用越懂你，才是 AI 的长期价值

[01:37:57] 第四，我整体的感受，再一次印证了之前说过的一个问题：干活这个事，前面我讲了复利。我觉得有一个核心思路，也应该作为心法沉淀：你手上的活，应该是越用越懂你的才对。

[01:38:27] 我们跟 AI 沟通，绝大部分话应该越讲越少，最后不需要讲明了，心有灵犀，嘴巴一动它就知道要干嘛。这一次设计的东西就有一个明显特点。

[01:38:52] 我每次工作，比如节点、转折、关键决策，后面都会提醒我要不要沉淀。一沉淀，它就会在我的记忆框架里，在多个维度上沉淀刚刚对话里的所有信息。这里面涉及大量工作记忆、路径记忆、决策记忆，对我个人特质的把握等等。

[01:39:18] 一路记下来，它已经相当了解我了。但唯独设计这个板块，之前没有全程落地过一个核心东西，尤其是体现我个人风格的东西。所以在这个板块上，它不懂它的伙伴，也就是我到底喜欢什么样的设计风格。

[01:39:38] 之前唯一有一个，是 Reader 的那个长文章页，用 HTML 设计的。因为 Reader 本身更多偏功能性，适合阅读。但它不了解我在设计这个板块上的倾向和偏好。这一块是空的。

[01:40:00] 这一次完成之后，我们的 design system、决策逻辑、审美偏向，整个过程都是全记录的。除了有一个打包完整的产物之外，上下文到 50 万时我也会沉淀一下。每个过程都会迭代它跟我的记忆。现在它就有了懂我设计偏好的可能性。

[01:40:29] 它的 memory 整理好了之后，还有对应索引表。关于设计相关的 memory 在哪里，对应索引文件在哪里。后面我希望，只要我嘴巴一动，说做个什么东西，在工作项目规范里写清楚：涉及前端设计时，优先参考整个工作区里沉淀好的工作系统。它只要有这么一个工作规范，就会直接调用这个东西去完成后续设计。

[01:41:08] 通用人工智能什么时候来？不知道，但这不重要。因为现在智能已经相当通用了。核心是，哪怕通用智能来了，如果你不知道怎么让它沉淀关于你的专属记忆，它通用就等于不属于你。你得让它属于你。

[01:41:24] 这些东西应该是越用越厚、越用越多的。我当时给你们举过例子：我的 AI 了解我非常细，细到我的设备、账号、资源、生活细节，它都知道。比如我有一块 Apple Watch Series 10，哪个版本，有没有蜂窝数据。我还让它去苹果官网把 Series 10 的 specification 找过来，放到“拥有的物件”那个板块。它理解我有这个 Apple Watch 能做什么。

[01:42:16] 这带来的效果就是：当时我在设计跑步表格的时候，它就提出来说，哥，你既然有 Apple Watch，每天充好电，带着它去跑步。跑完步回来打开苹果健身 App，把对应两页截图发给我，我就能给你登记跑步的所有数据。我们要的不就是这个效果吗？

[01:42:40] 有一次我没带表，我回来跟它讲，说今天没带手表。它就跟我说，没事，没带手表，如果你用 iPhone 拿在手里，iPhone 的健身 App 虽然测不了心率，但距离测定没有任何问题。今天的登记顶多少几个细节，不影响整体训练规划推进，你拿着手机去就可以了。

[01:43:07] 上次我们说输入输出越来越流畅的时候，我办了十几个平台、多少张银行卡。每一个办完，我给它沉淀，沉淀对应资料。每个资料我让它去网上调研，把相关关键信息整理下来。现在遇到任何复杂问题，我告诉它什么情况，它直接基于这些资料就能帮我解决问题，精准到哪张卡、哪个账户、到哪个网站登录、怎么操作。

[01:43:42] 这种东西算不算 AGI？我觉得当你把这些东西补给它的时候，这不就是 AGI 吗？已经算是了。它通用智能确实很强，只是说通用智能对你没有太大用。你要把它个性化、为自己系统定制。当你把智商 150 的通用智能跟你自己深度绑定，并进行系统化定制的时候，它就越用越懂你，越用越聪明。

[01:44:14] 所以今天设计这个过程，复利知识资产的沉淀，以及各个板块的通用，其实都是之前思路的一次关键印证。它可以赋能到你生活里的方方面面。

[01:44:32] 你看，以后网站会呈现这些东西。我们早就说过，尽量把所有东西全部数据化，跟你的 agent 接通。接通之后，网站呈现自然不是问题。像现在我的健身、跑步、心率、体重变化、饮食规划，它都留在那里。让它拉一下我跑步这么长时间的运动能力变化，它能有理有据地分析出一份心肺功能变化报告。这不是编着玩的，而是基于真实数据给我的。

[01:45:20] 所以很多时候，我个人觉得，你做一个事，不能把它想成单独开一个文件夹的独立项目。你真应该把你和 AI 想成一个共生体，类似汤老师和毒液的关系。更聪明、更强大，但它也确实需要理解你，跟你融合得越紧密越好，更多可能性才会诞生。

[01:45:55] 假设你个人表达素材非常丰富，提炼你的表达风格其实很简单。不要觉得这只是“真人表达风格”这么简单，而是它在让 AI 理解什么样的表达方式更像它主人。这样理解，这个活的意义就不仅仅是测试一个 skill。

[01:46:25] 有了它作为一个“王正宇语音包”或者表达风格包，又会变成通用资产。以后写任何东西、改写任何东西、整理任何东西，都把调用这个语音包当成一个单独技能。这就是我的 agent 理解的我的表达风格。把这个语音包调进去之后，所有东西出来都像我说的。

[01:46:48] 这种活有没有人干？有人干。很多人把它称为真人拟态、女娲之类，没毛病。但我觉得你的理解不应该停在“拟某个具体的人有什么价值”。你真正应该理解的是：一个人的表达风格、思想脉络，在 skill 或框架打磨之下，于 AI 而言变成了可见、稳定、可复利的资产。

[01:47:18] 你要这么理解问题，才能真正找到跟你的“毒液”共生的心态和状态。

[01:47:30] 因为要做好这件事，你才会把所有所谓真人 skill 当成调研对象去调研，然后挨个砸出来，看怎么样可以做得更好。说白了，通过网站设计，我用这种方式向我的 agent 证明了：我喜欢的东西是什么样子，我要的风格长什么样。

[01:47:51] 那你选择什么样的方式，让你的 agent 了解你的表达方式、语言逻辑呢？这个时候，所谓开源的真人 skill 类似什么？类似今天我们给它的十个参考网站。它们是参考，而不是说你知道有哪个 skill 可以拟真人，就不得了了。

[01:48:12] 为什么它就是最好的？为什么它就是拟你自己最好的？为什么它就是结合你的需求拟别人最好的？都不一定。它更像一种参考。真正向你说明的，是人机协作过程中两相共生的结构。汤老师和毒液的关系，我觉得就很能说明这个问题。

[01:48:42] 这样的东西应该拆解、意识到、沉淀下来、反思迭代。设计风格这种 design system，当前可能没有分单独版本，但后面迭代到 1.1，我可能就拆成两个风格、三个风格、四个风格。

### 八、隐私：现实地做取舍，但不要乱放明文

[01:49:05] 有人问，怎么确保保密防火墙密不透风。你这不是搞笑吗？AI 时代还有隐私吗？你想什么，还有隐私啊？

[01:49:27] 这个地方涉及另外一个逻辑。随着科学技术发展，人类一直都在面对一个道德困境：用隐私换便利，换不换？这么多年，我们一直在思考这个问题。口口声声都说隐私重要，但只要不是让人发表道德宣言和表态，大家都老老实实为了便利把隐私交出去了。不是吗？人类一路走过来就是这样。

[01:50:01] 尤其在中国，人们在中国有什么隐私？经历过疫情都知道，不说了。没什么隐私可言，无所谓了。对我来讲，所谓隐私，我认为自己能做到的最好保护，就是全套用苹果产品。如果要加一个附录，那就是用外版苹果产品，这就是我能做的保护隐私的唯一工作。再加一个，就是所有账号也都登外区账号，也仅此而已。其他就别想了。

[01:50:53] 现在的问题是：如果给了隐私换便利，收获大不大，划不划算？反正都没了，那交出去的话，我肯定要尽可能换来更大的收益。没了，也给了，东西还没换回来，那不搞笑了吗？

[01:51:11] 所以别想这个事。没有任何隐私的。这个事压根不是问题。

[01:51:20] 我唯一在乎的问题是：如果 OpenAI 和 Claude 这种大型 AI 公司，竟然真的依托用户在服务器上的对话记录去针对谁搞事情，那我觉得这两个价值万亿美金的公司真的没良心，也没办法。这就等于相信苹果这样的公司会出卖用户隐私一样。如果这种事发生，我们平头老百姓也管不了。

[01:51:47] 除此之外，就是尽量所有文件逻辑上留在本地，你的 agent 对文件有访问权限，也仅此而已。至于你电脑被别人攻克了，我都用 Mac 了，还能干什么？你把我 Mac 都攻破了，苹果都没能挡住你，那我还能说什么？那就是我惹上不该惹的人了。

[01:52:26] 金融账号的安全，不是你们理解的那样。不是明文写在文字里给到 agent。Agent 只知道这个东西可以去哪儿调，真的存在哪呢？存在类似 1Password、Google Password、Apple Password 这种地方。它存在的是巨型公司真正的数据库里，有自己的加密算法。

[01:52:55] Agent 要调用这个东西，有了 computer use 的话，核心就是调用之前让你再输一次电脑密码。我的核心是告诉它：密码我存在那儿了，你要调用就这么调，这条路径是通的。你不可能把密码明文写在文件里，那不是纯纯傻逼吗？

[01:53:20] 所以我还比较好奇，苹果新的 AI 策略后续到底会怎么解决 Apple Intelligence 的遗留问题。苹果一直是最保护用户隐私的公司。我很好奇，如果新的版本真的落地，端侧模型到底怎么解决用户隐私问题。

[01:54:01] 我看苹果的逻辑是用一套端侧模型，压根不往服务器传数据。用到云端强大模型时，背后也有一套很严格的加密算法，有对应的任何人无法访问的权限。我对这个挺感兴趣，也觉得很好玩。

[01:54:27] 其他的就别琢磨了。你隐私换便利，换了就换了。换了就躺了，无所谓。

### 九、工作区：不要让每个项目都变成孤岛

[01:54:39] 第四个，我觉得很重要的一件事，也有很明显的体会：现在做的很多活，相比未来我们能够料想到的东西，都只是一个开端。

[01:54:57] 两年前我们讲数据很重要、知识资产很重要。到 2026 年 Agent 时代一开启，当年的提醒就显出价值了。你自己数据多，你的表达风格就出来了；你数据多，你的设计风格就出来了；你工作逻辑清晰，你的工作者、你的 agent 就越来越懂你。

[01:55:20] 相比而言，没有历史记录、脑袋不清楚、不知道怎么跟 AI 协作的人，每一个 agent 跟你工作时，每次都像白板一样，那就很愚蠢。

[01:55:33] 所以我当时觉得，我跨入 Agent 时代迈得最好的一步，就是从一开始就没有用任何独立项目的工作区来跟 Agent 协作。我建的第一个文件夹就是 workstation，也就是我的工作站。我的 Claude.md 和 AGENTS.md 建在这个 workstation 当中，再把 workstation 分成每个板块，每个板块下面再对应具体项目。

[01:56:05] 我认为这是我迈入这个时代时做得最正确的一件事。这个工作区，就等于我和 AI 交互的界面，而不是某一个独立项目。

[01:56:17] 因为当你的目光锁定在独立项目时，你会发现，每一个 agent 针对一个项目与你的认知，如果没有可复用的指针性文件或可复用的背词文件，它对你的每次认知都是新的。或者说，全局配置文件里的 memory 会在各个独立项目中被分拆调用。

[01:56:47] 这就很愚蠢。它没有全局性的系统观念。项目是在整个系统里的，所以它对我的每一段记忆、每一段记录、每一个资产层面的理解，都首先发生在工作区这个大空间里。而这个工作区就代表它对我的所有理解。

[01:57:07] 所以我一路过来跟它的交互，全部稳定沉淀在一起。任何地方都能找到，不存在项目跟项目之间断档的问题。

[01:57:19] 我也非常建议你们使用这种方式。除非是需要极其干净环境的独立项目，需要单独拿出来；否则，有一个纯粹记录你和 AI 共生关系的完整工作区，再把东西往里面放，是管理起来相对更高效的方法。
